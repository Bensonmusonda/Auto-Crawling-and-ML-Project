# Crawling Workflow Guide

This guide explains how to use the **Web Scraper Configuration Extension** to visually define what data you want to collect, and then use the **Crawl Monitor** tab to execute and monitor the crawl job in real time.

---

## How the Crawling System Works

Unlike rigid, hardcoded scrapers, this system is entirely dynamic. It uses a **two-part architecture**:

1. **The Chrome Extension (Configuration):** A visual point-and-click tool that lets you select elements on a target webpage. It automatically builds robust CSS/XPath selectors and syncs this configuration directly to the backend.
2. **The Scrapy + Playwright Worker (Execution):** The backend dynamically loads the configuration you built with the extension and deploys **Celery workers** to scrape the site. Playwright ensures that dynamically loaded JavaScript elements are fully rendered before extraction. Progress is streamed back to your UI over **WebSockets**.

---

## Step 1 — Install the Configuration Extension

Before you can scrape, you must declare _what_ to pick up. You do this using the provided Chrome Extension.

1. Open Google Chrome and navigate to `chrome://extensions/`.
2. Turn on **Developer mode** (toggle in the top-right corner).
3. Click **Load unpacked** and choose the `extension/` directory from the root of this project.
4. Pin the extension to your toolbar—you’ll use it frequently.

---

## Step 2 — Visually Map the Website

1. In Chrome, navigate to the target website (e.g., an Amazon category page or a Steam search result).
2. Click the scraper extension icon in your toolbar.
3. Use the **Inspector / Start Selecting** tool. As you move your mouse over the page, elements will highlight.
4. Click on the actual data points you want to scrape (e.g., the title text, the price tag, the review count). The extension will calculate the most resilient selector for that element.
5. Assign a clear **Label** to the selector in the extension popup (e.g., `Price`, `Product_Name`, `Rating`).
6. Click **Sync to Backend**. Your custom scraping rules are now securely stored in the platform!

---

## Step 3 — Execute the Crawl

With your rules synced, head over to the platform UI to start the job.

1. Click **Crawl Monitor** in the left sidebar. Make sure the WebSocket status indicator at the bottom says **Connected**.
2. Fill in the crawl form:

| Field            | Description                                                                           | Example                                                  |
| ---------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| **Target URL**   | The root URL where the spider begins its crawl.                                       | `https://store.steampowered.com/search/?sort_by=Reviews` |
| **Dataset Name** | The name of the output CSV file that will be generated.                               | `steam_games_v1`                                         |
| **Max Pages**    | Hard cap on the number of linked pages visited. Safety net to prevent infinite loops. | `50`                                                     |

3. Click **Start Crawl**. The system applies your extension-synced configuration and dispatches the Celery worker.

---

## Step 4 — Monitor Progress in Real Time

Once running, the **Live Jobs** table automatically updates. Each active run shows:

- **Status** — `queued` → `running` → `completed` or `failed`
- **Pages Crawled** — How many links the spider has successfully parsed.
- **Items Scraped** — Total rows of data matching the selectors you picked in Step 2.
- **Last Event** — Timestamp of the most recent progress update.

Below the table, the **Event Log** streams the raw messages directly from the Celery worker via Redis Pub/Sub, so you can see exactly which child-URLs are being parsed or if any HTTP 403 blocks occur.

---

## Step 5 — Access the Dataset

When the job completes, navigate to the **Datasets** tab. Your freshly scraped CSV will immediately appear in the list.

- **Preview** — Inspect the first 100 rows directly in the browser to ensure the extension picked up the correct elements.
- **Process** — Jump to the Data Processing tab to clean text artifacts (like stripping `"£"` signs using _Extract Number_).
- **Train** — Move the dataset into the ML Pipeline.

## Troubleshooting

**The job completes, but Items Scraped stays at 0**
The spider successfully loaded the pages but couldn't find your data. This happens if the visual CSS selectors generated by the extension are too specific to a single page and don't generalize to other pages on the site. Open the extension again, select a more generic container class, and re-sync.

**Job fails immediately or Event Log shows timeouts**
The target site might use heavy bot-mitigation (e.g., Cloudflare). Playwright handles a lot, but aggressive crawling can still trigger CAPTCHAs. Try reducing your concurrent connections or implementing proxy rotations in the Scrapy settings.

**Dataset not appearing in the Datasets tab**
The CSV is written to `/app/datasets/` inside the Docker container. Check that your `.env` or `docker-compose.yaml` volume mounts correctly map `./backend/datasets` to `/app/datasets`.
